# 技能编写规范

格式依据 [Agent Skills 规范](https://agentskills.io/specification)。以下示例仅为文档，不是待安装技能。

默认使用简体中文编写技能描述、正文、配套说明和面向用户的提示。标准字段名、目录名、命令与 API 标识保留原文。

## 目录与元数据

技能放在 `skills/nexusflow-<task>/`，名称与目录一致，使用小写英文字母、数字和单连字符，最多 64 字符。
这是本仓库的命名约定。每个技能至少包含 `SKILL.md`：

```yaml
---
name: nexusflow-example
description: 说明完成什么任务，以及用户在什么情况下应使用此技能。
license: MIT
compatibility: 写明实际需要的运行环境；无特殊要求时删除此字段。
metadata:
  nexusflow-platform: "待验证"
  nexusflow-sdk: "不需要或待验证"
---
```

`metadata` 是自定义字符串映射，不会让客户端自动安装依赖或强制版本检查。
技能包版本统一记录在根目录 `VERSION`，不在每个技能内重复维护版本。

## 正文内容

按任务需要组织以下内容，避免空泛指令：

1. 适用任务、触发条件与不适用范围。
2. 前置条件、权限、输入与缺失信息的处理。
3. 可执行步骤：优先使用公开 SDK/MCP/API，说明实际依赖。
4. 成功标准：检查真实状态和输出，不只检查请求是否成功。
5. 错误与恢复：认证失败、权限不足、任务失败、超时或版本不兼容。
6. 输入输出示例及验证方法。

正文尽量少于 500 行；细节放入 `references/`，脚本放入 `scripts/`，模板与静态数据放入 `assets/`。
至少提供一个明确的触发示例和一个不应触发的反例。

## 可移植性

- 一个技能目录就是一个独立分发单元。资源引用使用目录内相对路径。
- 不引用开发者本机路径、相邻技能或仓库外文件。公共执行逻辑优先复用有版本的 SDK。
- 不写死某个客户端的专用工具名；确需专用能力时明确标记兼容范围。
- 不内置平台访问令牌、生产账号或客户数据。`.env.example` 只使用占位值。
- Markdown 链接中的本地路径使用普通相对路径；空格用 `%20` 编码。
- 脚本依赖、第三方许可和必要配置说明随技能一同分发。

## 校验边界

仓库工具检查元数据、命名、正文、部分不应发布的文件及普通 Markdown 本地链接。
不执行技能脚本，不验证网络链接，不解析代码块、HTML 或引用式 Markdown 链接中的依赖，也不判断模型执行效果。
发布前仍须人工审阅全部文件引用，并在声明支持的客户端中验证真实任务。
