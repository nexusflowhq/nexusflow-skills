# 目标适配与执行

## 版本适配

记录目标平台版本、求解镜像及组件库版本；使用当前可用官方接口/SDK或用户提供的导入导出结构。先读取组件默认定义、枚举、端口和最小导出样例，不凭经验虚构 REST 路径。

建议适配器分层：`extract → normalize → validate → emit → platform validate → solve → compare`。每层输入输出用 JSON/CSV，确定性 ID 映射避免重复执行生成重名元件。适配器需单独验证；随附离线工具不生成平台 payload。

连接参数可采用 NEXUSFLOW_URL、NEXUSFLOW_WORKSPACE 和运行时凭据，名称只是使用约定，不代表 SDK 自动支持。不得在脚本、报告或日志中保存秘密。公开包不包含 .env、客户端会话、导出模型或运行日志。

## 修改控制

优先生成新候选算例或本地候选 JSON，保存当前版本与内容哈希。变更表至少列组件 ID、字段、原值、新值、单位、依据、等价性和未解决问题。

用户已授权创建、修改或计算时完成相应工作；只有用户明确要求“先看清单再改”时在外部写入前等待确认。发布开源仓库不包含在模型转换或 skill 创建授权内。

更新既有模型前重新读取，若与基线不同则避免覆盖并发修改。成功上传后读回关键字段、组件计数及全时序曲线；不以 HTTP 成功代替模型校验。提交求解记录任务 ID，网络超时先查询任务避免重复提交。校验失败或相同求解失败重复出现时停止自动重跑，输出具体阻断和诊断。

关闭状态、边界类型、单位、气质、流量符号、硬约束和拓扑必须通过校验。无依据的阀阻、粗糙度或边界重构不能在后台自动优化。
