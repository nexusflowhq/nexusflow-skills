# 发布流程

## 发布前

1. 确认技能的实际任务测试通过，兼容性记录和 README 技能目录已更新。
2. 检查凭据、私有地址、第三方许可和资源完整性。
3. 更新 `VERSION`（格式为 `主版本.次版本.修订版本`），将“未发布”内容整理为带版本号和日期的中文更新记录。
4. 运行校验、工具测试和打包，解压单技能包并在目标客户端验证。

```bash
python scripts/validate.py
python -m unittest discover -s tests -v
python scripts/package.py
```

没有技能时校验通过，打包明确拒绝；不会发布空技能包。
打包默认输出到 `dist/<版本>/`：单技能 ZIP、完整集合 ZIP 和 `SHA256SUMS.txt`。
每次输出目录必须为空，以免将旧文件混入新发行版。

## 版本规则

- 修订版本：保持原有输入输出及依赖要求的修复。
- 次版本：新增技能或兼容的能力扩展。
- 主版本：不兼容的输入输出变化、移除能力或提高必要依赖要求。

在 0.x 阶段，不兼容变化也必须在更新记录中明确标出。旧包保留，便于回退。

## GitHub 流程

仓库公开前，设置仓库信息、私密漏洞报告渠道、维护者和主分支保护规则。

合并发布提交后，推送与 `VERSION` 一致的 `vX.Y.Z` 标签，会触发发布工作流：

1. 校验版本与标签一致，运行检查和测试。
2. 生成发布文件并上传至 GitHub **草稿发行版（Release）**。
3. 维护者确认下载包、兼容性及发行说明后，手动正式发布。

工作流不会自动把草稿公开。若同名发行版已存在，流程将失败，维护者应检查已有草稿及附件，不要移动已发布标签。
本地骨架阶段尚未配置 GitHub 远程仓库，也未触发任何远程流程。
